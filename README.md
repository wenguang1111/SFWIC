# 临港对决 · Harbor Clash

以《拳皇 ’97》的**四键、方向指令、取消连招与角色辨识度**为参考的原创键盘格斗游戏。当前是本地 **1P 对 CPU** 与**练习模式**，四名角色、夜港与冰场两个舞台，默认选中暂名「冰上少女」的花滑角色。只借鉴机制，不是原作复刻：没有使用原作代码、角色、图像、音轨或招式名，也没有联网对战。

连招与指令体系的完整设计（连招类型库、角色招式与代表连招、指令记法）见 [docs/combos.md](docs/combos.md)。

## 运行与部署

```sh
python3 -m http.server 8147 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8147/
```

无需安装依赖或构建。将 `index.html`、`style.css`、`main.js`、`src/`、`assets/` 保持相对位置部署到静态站点即可（包括子目录）。不要用 `file://` 双击入口，浏览器需要通过 HTTP 加载 ES modules。规则测试：`npm test`（Node 22+）。

## 玩家看到什么，为什么

- **开局先看招式表。** 左侧选人，角色档案显示主连招类型和一条代表连招；右侧招式表按「普通技与指令技 / 必杀技 / 超必杀 / 防守技」分组，指令直接写成箭头与键位（如 `↓↘→ + 拳(J/U)`），通用的站 / 蹲 / 跳普通技折叠在第一组里。选一个本局目标再开打；目标只提供反馈，不改变胜负条件。
- **战场让出中线和脚底。** 上方对称排列生命、能量与倒计时，能量条中点刻有 50 的超必杀线。连段时攻击方一侧显示「4 HITS · 38」这样的段数与累计伤害，连段中断后淡出。下方显示任务进度。
- **连招靠取消接上。** 轻攻击可以互相连打；轻攻击与近身重攻击命中或被防的瞬间输入必杀技或超必杀即可取消。命中停顿让每一击有分量。能量来自实际接触，超必杀消耗 50。
- **60 秒单局。** 生命归零即结束；超时比较剩余生命，相等为平。失去窗口焦点会暂停；结算可与同一对手再战或返回选人。
- **练习模式。** 在本场目标下方勾选「练习模式」：不计时，陪练不走 CPU、站着不动，可选不防御 / 站防 / 蹲防（站防只在你出招或飞行道具在场时按后，不会一路退到版边）。任务照常计数，适合练三连段与指令。

### 四种连招类型

| 角色 | 主连招类型 | 招牌 | 代表连招 |
|---|---|---|---|
| 烬 · 疾攻 | 派生连段 + 升龙 | 炎牙三段 236P×3；升炎 623P；赤焰冲 214K；超必杀 焚天 | 近 C → 炎牙 → 炎牙·贰 → 炎牙·叁 |
| 澜 · 牵制 | 蓄力 + 飞行道具 + 当身 | 潮弹 [4]6P；潮升 [2]8K；落潮掌 6C 破蹲防；回流当身；超必杀 怒涛 | 2B → 2B → 潮弹；对空用潮升 |
| 岳 · 重压 | 指令投 + 地波 | 山崩摔 41236P；地鸣 236K；磐石进 214P 可硬吃一击；超必杀 天地返 | 2B → 地鸣；或贴身逼防御后山崩摔 |
| 冰上少女 · 滑步 | 旋转连踢 + 突进 | 旋风连转 214K；阿克塞尔 623K 对空；冰弧突进 236P；蹲 D 蹲转扫；超必杀 三周半·终曲 | 跳 D → 站 D → 旋风连转；对空阿克塞尔 |

### 本轮花滑设计

- **身份与场地。** `skater` 暂名「冰上少女」，不编造真人姓名；冰鞋和花样滑冰是核心，不改成普通拳手。选人页面保留 **SATURN ARENA / Ingolstadt** 标识。任一方为 `skater` 时，`main.js` 将比赛状态的 `stageId` 设为 `saturn`，标题切换为冰场；其他组合用 `harbor`，保留港区夜场。舞台只改变画面，不改变比赛规则。
- **旋转是她的连招。** 必杀技全是旋转腿或滑行，对应花滑的旋转（spin）与阿克塞尔跳（axel）；冰刀只是脚下的滑行工具，不当砍人的武器。新招式复用已确认的真实动作帧，不用代码扭曲人体。
- **动作先画对，再接规则。** 用图像模型依据已确认的全身参考制作真实的待机、滑行、跳蹲、格挡、受击、倒地与招式关键姿势，再登记到 `assets/skins.js`。代码可以切帧、按统一脚底锚点摆放和整体左右镜像，不能用局部旋转、拉伸、倾斜或拼接鞋跟去伪造人体动作；尤其不能把脚尖的纵深转向误做成整只冰鞋的平面旋转。

### 键盘约定

| 输入 | 结果 |
|---|---|
| A / D 或 ← / → | 移动。地面按住**远离对手**的方向站防；换边后方向反转 |
| S 或 ↓；下 + 后 | 下蹲；蹲防。站防挡上段与中段；蹲防挡中段与低段 |
| W 或 ↑ | 跳跃，配合方向斜跳；落地时仍按住会再跳 |
| J / K / U / I | A 轻拳 / B 轻脚 / C 重拳 / D 重脚；只认按下那一下，不因键盘重复事件连发 |
| J + K | 同时按下（3 帧内先后也算）：角色专属防守技，不耗能，有冷却 |
| 近身 ← / → + U | 普通投，无视防御 |
| ↓↘→ + J/U 等 | 指令技。招式表的数字记法以**面朝右**为准，面朝左时自动镜像；「拳」= J 或 U，「脚」= K 或 I；`[4]6` 表示按住后方向蓄力再推前 |
| Esc | 暂停 / 继续；打开按键指南时也会暂停对战 |

取舍：没有 3 人队伍、双人同屏、联网或触屏键位。

## 开发接口

分离会独立变化的内容：**规则、招式数据、输入、画面、任务**。不为每个角色复制一份主循环。

| 改动 | 入口 | 不变量 |
|---|---|---|
| 新增角色 | `src/roster.js` 的 `fighters` | 唯一 `id`；`archetype`（`rekka` / `charge` / `grappler` / `spin`，界面显示为主连招类型）、`combo`（代表连招文本，界面会把记法转成箭头）、外观与移动参数；`moves` 以招式 id 为键，用 `src/moves/archetypes.js` 的模板组合。界面、招式表从数据生成 |
| 新增连招 / 必杀模板 | `src/moves/archetypes.js` | 一个模板是返回招式对象的工厂函数（字段见下）；指令 `input.motion` 只能用引擎已识别的 `236 623 214 41236 236236 [4]6 [2]8`。新动作类型才需要改 `src/combat.js` 并补测试 |
| 改一招的手感 | 对应招式对象 | 数值用 60 Hz 帧和逻辑像素；`timing` 为起手 / 有效 / 收招，`hitstun`/`blockstun` 决定能否连上；`cancel`、`chain`、`followUp` 决定取消去向；横向距离从角色中心算，纵向区间相对脚底 |
| 增加一种行为机制 | `src/combat.js` | `step(state, playerInput, opponentInput?)` 一次只推进一帧；不读 DOM，不播放动画；CPU 也经由输入驱动；给出 `opponentInput` 时绕过 CPU（练习模式与测试用） |
| 增加练习任务 | `src/missions.js` 新增 `{id, name, goal, description, counts(event)}` | 根据已结算的事件累计。`event.move` 是类别 `light heavy special super throw`，`event.moveId` 是具体招式，`event.combo` 是该击后的连段数。例：三连段 `e.type === 'hit' && e.attacker === 0 && e.combo >= 3` |
| 换头像或动作画面 | `assets/skins.js`；渲染入口 `src/art.js` | 图片异步加载；不从图像推断伤害、距离或动作时长 |
| 改键位 / 流程 | `src/input.js` / `main.js` | 输入每帧为 `{up, down, left, right}`（按住）与 `{a, b, c, d}`（只在按下那帧为真）；界面文字同步更新 |

**新增一名角色的步骤**：① 从 [docs/combos.md](docs/combos.md) 第 2 节挑一种主连招类型与 2–4 个模板；② 在 `src/roster.js` 组合模板、填数值，写 `name`、`description`、`notation`（如 `'236P'`，界面自动显示为 `↓↘→ + 拳(J/U)`）、`archetype` 与 `combo`；③ 在 `assets/skins.js` 按招式 id（或招式的 `anim`）登记图集帧。不需要改界面或主循环。

招式对象的主要字段：`{ id, name, description, kind: 'normal'|'command'|'special'|'super'|'throw'|'defense', input: { motion?, button, stance?, near?, forward? }, notation, pose, anim?, vfx?, level, damage, reach, band, timing, drive, hits?, hitstun, blockstun, knockdown?, chain?, cancel?, followUp?, projectile?, invulnerable?, armor?, cost? }`。

**招式制作单**：`角色 / 招式 / 指令 / 玩家意图 / 可被什么克制 / 起手·有效·收招帧 / 受击·被防硬直 / 可取消去向 / 段位·范围·位移 / 关键姿势 / 命中与格挡反馈`。先调灰盒判定，再按生效那一帧对齐图集。低扫的亮部放在脚踝，高掌先抬肩，防守特效不能盖住下一招起手。如果改动作让它看上去打得更远，也要回头核对 `reach`，不要只放大特效。

### 从一张头像到可部署动作

1. **锁定身份与画风。** 用授权人像、已有的满意样图和同一份配色/服装说明，产出透明底半身像。单张头像能确定脸和发型，不能确定身高、全身服装或连续帧。不要为每一帧独立生成一张人像。
2. **锁定全身参考。** 先确定向右侧身的待机全身图（含鞋）、主副色、惯用手、四肢比例和统一光源。近手/远手用明度分开。战斗中同一角色左右翻转，非对称细节要接受镜像或另外安排制作。
   冰上少女的冰鞋刀架内部应保留真实透明空隙；舞台保留 Ingolstadt 与 SATURN ARENA 背景标识。鞋尖、鞋跟与冰刀轴的透视应由姿势图本身一致表达，而不是运行时代码扭曲。外貌与鞋型以用户确认的参考图为准，不将尚未确认的修订当成定稿。
3. **按招交付。** 先做待机和一个招牌动作的起手／命中／回收三张关键姿势，验证辨识度、脚底锚点、打击距离，再扩展到移动、跳蹲、防守、受击等。头像和每个姿势可分别替换，不必等整套完成。
   花滑新增动作按「滑行方向与支撑脚 → 起手／有效／收招关键姿势 → 模型出图 → 人工确认四肢与冰鞋透视 → 透明底清理和逐帧切图 → 脚底锚点与持续帧登记」扩展。清理背景、裁切、对齐不改变身体结构；若姿势或鞋跟画错，回到模型编辑参考图，不以代码变形掩盖。检查旋转踢的支撑腿、滑行时的刀刃接地、跳跃落地与收招重心是否连贯。
4. **登记资产。** 将自有 PNG 与 `assets/skins.js` 一起提交；`portrait` 和 `sheet` 路径相对该文件。以下为 *有相应图片时* 的条目示例：

```js
jin: {
  portrait: './jin/portrait.png',
  sheet: './jin/combat.png',
  scale: 2,
  frames: {
    emberFang1: {
      // 源图 x, y, 宽, 高, 脚底锚点 x, y, 持续逻辑帧数
      [0,   0, 80, 72, 32, 69, 6], // 起手
      [80,  0, 80, 72, 32, 69, 3], // 有效
      [160, 0, 80, 72, 32, 69, 11], // 收招
    ],
  },
}
```

帧键先找招式的 `anim`（缺省为招式 id，例如 `emberFang1`、`spinChain`），找不到再退回姿势键 `idle walk crouch jump guard light heavy special defense hurt ko`。无外置素材时使用内建像素画。示例的 6/3/11 帧仅为对齐说明；不要将切图坐标、图像缩放倍数与攻击范围混用。

新角色可在自己的皮肤条目写 `base: 'jin'`、`'lan'` 或 `'yue'`，选择继承哪套内建动效；不写默认用烬。图片可以覆盖已有姿势；要增加三套风格以外的新粒子轨迹或地波形状，改 `src/effects.js`。不要为一张新头像新建战斗类。

给支持**参考图编辑、透明底输出**的图像模型，可从这段开始：  
「图 A 是获准使用的人物参考，保留脸型、发际线和眉眼；图 B 仅参考色阶与像素密度。制作原创 90 年代街机格斗选人半身像，[主色] 的 [外套]，[表情]，三分之四侧脸、左上硬光、有限色板和清晰外轮廓。透明背景，不加字、标志或界面。先交一张定稿，不生成动作序列。」先看缩成选人卡后是否仍能认出本人，再拿定稿做全身图。

## 下一轮请提供什么

**先发一个人，不必一次准备全阵容。** 最有价值的是：

- 一张已确认可用于此游戏的头像（或授权照片），以及你之前生成、最认可的一张风格样图。可附原提示词；不用发送账号或未打算公开的个人资料。
- 一张全身照，**或**一段服装与体型描述：外套轮廓、鞋、主色、一个一眼能认出的细节。不愿上传更多照片时可完全虚构服装与身形。
- 一张文字角色卡：`显示名｜主打法｜最想看到的一招｜防守倾向｜不能改的外貌细节`。不知道怎么选时，只回答「追着打 / 保持距离 / 等人过来」之一即可。
- 确认发布范围，以及人物本人/素材权利人是否允许肖像用于该范围和 AI 风格化处理。代码的 MIT 许可不自动代表有权发布以后加入的照片。

**优先决定两件事**：① 第一名真人角色套用哪种连招类型（见 [docs/combos.md](docs/combos.md) 第 2 节）；② 正式首发保持 1 对 1 键盘，还是必须有三人队伍、本地双打或触屏。后者会改变开局布局、键位预算与动作资产量，宜在批量制图前决定。
